# Agent开发学习记录

# Agent,Workflow

Agent和Workflow之间并非割裂的个体。Workflow更像是一个人为进行规范化流程的过程，更加具有确定性。但当可能的运行分支过多，或需要进行意图性的判断而非直接的运行时，需要使用Agent进行一些思维上和选择上的拓展。当然可以将Agent嵌入Workflow中作为节点，提升系统性能。



# Agent

Agent是对于LLM一种封装模式，LLM是对于文字的预测模型。Agent在LLM的基础上增加能力以保障实际的体验。即Agent = LLM + 记忆 + 工具 + 编排

记忆：能够获取前后对话的联系，记录使用者的偏好等。

工具：LLM不具备直接进行交互的能力，工具赋予这一点。

编排：是Agent增加的思维模式，使得整体工作更加有效。

## 编排

### ReAct

全称是Reasoning-Action，其主要过程是 思考 -> 行动 -> 观察 循环，在多次循环中不断更新当前的目标，以接近最终目的。但这种迭代容易陷入局部最优。

### Plan-and-Execute

是针对陷入局部最优的一种解决方案，它在一开始就自顶向下确定了实现方案，一步步走就行。成熟的该方案可以子啊过程中进行动态提哦啊正。

### Reflection

是记忆系统的加入的模式，它是对前两种的扩展，通过记忆系统在不断循环迭代的过程中记录一些记忆，使得可以依靠经验快速高效解决问题。

## 记忆

感知记忆：用户的原始输入，单次访问即可

短期记忆：上下文中的messages列表，即用户输入、模型输出、工具调用结果等。 **直接存储在内存+TTL自动清理。**

长期记忆：

情节记忆：时间情节，比如上周问了什么。 **SQLite（结构化数据和复杂查询，时间、重要性等）+Qdrant（高效的向量检索）**

语义记忆：多次流程中获得的实践经验。 Neo4j(图数据库，关系)+Qdrant（向量数据库）

程序记忆：总结得到的某件事的运行流程。

实体记忆：关键事实，比如用户偏好。

### 记忆梳理：

去重：合并相似度高的记忆。

冲突消解：矛盾记忆保存最近的。

抽象提炼：情节记忆 -> 语义记忆。

### 记忆压缩

摘要压缩：把长对话总结成简短摘要

### RAG

![image-20260508204804914](https://cdn.jsdelivr.net/gh/Eureka-24/img@main/img/20260508204804953.png)

多查询扩展（Multi-Query Expansion）是一种通过生成语义等价的多样化查询来提高检索召回率的技术。这种方法的核心洞察是：同一个问题可以有多种不同的表述方式，而不同的表述可能匹配到不同的相关文档。例如，"如何学习Python"可以扩展为"Python入门教程"、"Python学习方法"、"Python编程指南"等多个查询。通过并行执行这些扩展查询并合并结果，系统能够覆盖更广泛的相关文档，避免因用词差异而遗漏重要信息。

假设文档嵌入（Hypothetical Document Embeddings，HyDE）是一种创新的检索技术，它的核心思想是"用答案找答案"。传统的检索方法是用问题去匹配文档，但问题和答案在语义空间中的分布往往存在差异——问题通常是疑问句，而文档内容是陈述句。HyDE通过让LLM先生成一个假设性的答案段落，然后用这个答案段落去检索真实文档，从而缩小了查询和文档之间的语义鸿沟。
